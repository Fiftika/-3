  1. ЧТО ТАКОЕ ЭТОТ БЕКЕНД И ЗАЧЕМ ОН НУЖЕН
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Раньше сайт работал полностью в браузере:
  - Посетители добавляли героев / фото / письма
  - Всё сохранялось только в localStorage браузера
  - Данные исчезали при очистке браузера
  - Никакой модерации не было — любой мог добавить что угодно

Теперь с бекендом на Django:
  - Данные хранятся в настоящей базе данных (файл db.sqlite3)
  - Добавленные записи сначала попадают на проверку к администратору
  - Только после одобрения запись появляется у всех посетителей
  - Администратор может редактировать тексты прямо в панели
  - Система автоматически проверяет орфографию и показывает ошибки
  - Сервер работает постоянно, данные не теряются

Технически: это веб-сервер Python/Django, который отдаёт страницу
сайта и предоставляет REST API для сохранения данных в SQLite.

ШАГ 1 — Установка пакетов Python
──────────────────────────────────
Введи команду (интернет нужен):

    python -m pip install -r requirements.txt

Что скачивается:
  - Django 4.2       — веб-фреймворк (основа всего)
  - Pillow           — работа с изображениями
  - pyspellchecker   — проверка орфографии (русский словарь)

Ждёт установки 1–3 минуты. Успешный результат выглядит так:
  Successfully installed Django-4.2.x asgiref-x.x sqlparse-x.x ...

ОШИБКА "pip не является командой"?
  Попробуй: python -m pip install -r requirements.txt
  Или:      py -m pip install -r requirements.txt


ШАГ 2 — Подготовка HTML-шаблона
─────────────────────────────────
    python setup_template.py

Что делает этот скрипт:
  - Копирует wwii_album.html → templates\index.html
  - Добавляет в начало файла строку: {% load static %}
  - Добавляет перед </body>: подключение к api_override.js
  (Оригинальный wwii_album.html НЕ изменяется)

Успешный результат:
  Копирую wwii_album.html -> templates/index.html ...
  + {% load static %} добавлен в начало файла
  + api_override.js добавлен перед </body>
  Готово! templates/index.html создан (9.4 MB)

ОШИБКА "файл не найден"?
  Убедись, что wwii_album.html лежит прямо в папке "История сайт"
  (не в wwii_backend, а на уровень выше)


ШАГ 3 — Создание базы данных
──────────────────────────────
    python manage.py migrate

Что происходит:
  - Django создаёт файл db.sqlite3 (база данных)
  - Создаёт таблицы: пользователи, сессии, герои, фото, письма
  - Записывает историю изменений

Успешный результат — список строк "Applying ... OK":
  Applying content.0001_initial... OK
  Applying sessions.0001_initial... OK
  ...

Файл db.sqlite3 появится в папке wwii_backend\ — это и есть
вся база данных. Его можно копировать для резервной копии.

ВАРИАНТ А — Уже готовый аккаунт (создан автоматически):

ВАРИАНТ В — Сбросить пароль существующего:
    python manage.py changepassword admin

Каждый раз когда хочешь открыть сайт:

  1. Открой cmd в папке wwii_backend\ (см. Шаг 0 выше)

  2. Введи команду:
         python manage.py runserver 8080

  3. Подожди появления строки:
         Starting development server at http://127.0.0.1:8080/

  4. Не закрывай это окно cmd — пока оно открыто, сервер работает!

  5. Открой браузер и перейди по адресу:
         http://127.0.0.1:8080/

Заметка о порте:
  8080 — номер порта. Если порт занят (ошибка "address already in use"),
  используй другой, например 8090:
      python manage.py runserver 8090
  Тогда адрес будет: http://127.0.0.1:8090/

  - Другой человек открывает: http://192.168.1.5:8080/

8.1 ПРОСМОТР СПИСКА ЗАПИСЕЙ
────────────────────────────
Нажми на "Герои войны" (или "Фото хроники" / "Письма с фронта").

Увидишь таблицу со столбцами:
  ┌──────────────┬──────────┬───────────┬──────────┬──────────────┐
  │ Имя          │ Звание   │ Статус    │ Фото     │ Правописание │
  ├──────────────┼──────────┼───────────┼──────────┼──────────────┤
  │ Тест Иванов  │ Капитан  │ ОЖИДАЕТ   │ [миниат] │ ⚠ 2 слов     │
  │ Жуков Г.К.   │ Маршал   │ ОДОБРЕНО  │ [миниат] │ ✓ ОК         │
  └──────────────┴──────────┴───────────┴──────────┴──────────────┘

  ОЖИДАЕТ (оранжевый) — запись добавлена пользователем, ещё не видна
  ОДОБРЕНО (зелёный) — запись одобрена, видна всем на сайте

Фильтры справа:
  - По статусу: "Одобрено" / "Не одобрено"
  - По дате добавления: Сегодня / Эта неделя / Этот месяц

Поиск (поле вверху):
  - Для героев: ищет по имени, званию, биографии, наградам
  - Для писем: ищет по автору, тексту, году


8.2 КАК ОТКРЫТЬ И ПРОВЕРИТЬ ЗАПИСЬ
────────────────────────────────────
Нажми на имя записи в списке (подчёркнутый текст).

Откроется страница редактирования с разделами:

  [Основная информация]
    Имя / звание / годы жизни / воинская часть / награды
    → Всё это можно исправить прямо здесь

  [Биография] или [Текст письма]
    → Большое текстовое поле, можно редактировать

  [Фотография]
    → Показывается превью загруженного фото

  [Модерация] ← САМОЕ ВАЖНОЕ
    □ Одобрено ← поставь галочку чтобы запись появилась на сайте
    Орфографические ошибки: [список слов, если есть]

  [Служебная информация] (свёрнуто)
    UUID, ключ сессии, дата добавления

После редактирования нажми одну из кнопок внизу:
  [Сохранить и продолжить редактирование]
  [Сохранить и добавить ещё]
  [СОХРАНИТЬ] ← возвращает к списку


8.3 КАК ОДОБРИТЬ ЗАПИСЬ
─────────────────────────
СПОСОБ 1 — Открыть и одобрить одну запись:
  а) Нажми на запись в списке
  б) В разделе "Модерация" поставь галочку "Одобрено"
  г) Нажми кнопку [СОХРАНИТЬ]
  Запись сразу появится на сайте для всех посетителей.

СПОСОБ 2 — Одобрить сразу несколько (массовое действие):
  а) В списке отметь нужные записи (чекбоксы слева от каждой строки)
  б) Чтобы выбрать ВСЕ — поставь галочку в шапке таблицы
  в) В выпадающем меню "Действие" выбери:
       "✅ Одобрить выбранные записи"
  г) Нажми кнопку [Выполнить]
  Все отмеченные записи одобрены за один клик.

СПОСОБ 3 — Снять одобрение (если нужно убрать запись с сайта):
  а) Отметь запись в списке
  б) В "Действие" выбери "❌ Снять одобрение"
  в) Нажми [Выполнить]
  Запись скрывается с сайта, но не удаляется из базы.


8.4 КАК УДАЛИТЬ ЗАПИСЬ
────────────────────────
ВАРИАНТ 1 — Из страницы редактирования:
  а) Открой запись (нажми на неё в списке)
  б) Внизу страницы есть красная кнопка [Удалить]
  в) Подтверди удаление

ВАРИАНТ 2 — Из списка (несколько сразу):
  а) Отметь чекбоксы нужных записей
  б) В "Действие" выбери "Delete selected ..."
  в) Нажми [Выполнить], подтверди

Внимание: удаление необратимо! Запись исчезнет из базы навсегда.
Если хочешь просто спрятать — используй "Снять одобрение".


8.5 ПОНИМАНИЕ КОЛОНКИ "ПРАВОПИСАНИЕ"
──────────────────────────────────────
Когда пользователь добавляет запись, система автоматически
проверяет текст на орфографические ошибки.

В колонке "Правописание" ты видишь:
  ✓ ОК          — ошибок не найдено
  ⚠ 3 слов      — найдено 3 слова с возможными ошибками

Наведи курсор на "⚠ 3 слов" — появится подсказка с самими словами.

Важно: это автоматическая проверка, она не идеальна.
  - Редкие имена (Потапов, Хабаровск) могут считаться ошибками
  - Военные термины (Рейхстаг, вермахт) — тоже возможно
  - Перед одобрением проверь текст глазами сам

На странице редактирования в разделе "Орфографические ошибки"
показан полный список подозрительных слов.

  б) Нажми [+ Добавить пользователя]
  в) Введи логин и пароль
  г) После сохранения — открой пользователя снова
  д) Поставь галочки "Staff status" и "Superuser status"
  е) Сохрани

Или через командную строку:
    python manage.py createsuperuser

  9. ЧТО ВИДИТ ПОЛЬЗОВАТЕЛЬ САЙТА
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Пользователь заходит на сайт и:
  1. Видит все стандартные материалы (хроника, 19 героев, 10 писем)
  2. Видит все ОДОБРЕННЫЕ пользовательские записи
  3. НЕ видит чужие неодобренные записи

Когда пользователь нажимает "+ Добавить":
  - Заполняет форму (имя, биография, фото и т.д.)
  - Нажимает "Сохранить"
  - Видит своё добавление СРАЗУ (со своего браузера)
  - Видит пометку "Ожидает проверки администратором"
  - Запись приходит тебе на проверку в панель администратора

После твоего одобрения:
  - Запись становится видна ВСЕМ посетителям
  - Пометка "ожидает" пропадает

Пользователь может удалить только СВОЮ запись (и только из того
браузера, где добавлял — пока не прошло 30 дней).

  10. КАК РАБОТАЕТ ПРОВЕРКА ОРФОГРАФИИ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Используется Python-библиотека pyspellchecker с русским словарём.

Как это происходит технически:
  1. Пользователь отправляет текст на сервер
  2. Сервер извлекает все русские слова (минимум 3 буквы)
  3. Сравнивает со словарём pyspellchecker
  4. Возвращает список слов, которых нет в словаре
  5. Эти слова сохраняются в поле "spell_errors" в базе данных
  6. Администратор видит их в панели управления

Что проверяется: только русские слова.
Что НЕ проверяется: числа, даты, имена файлов, URL.

Ограничения словаря:
  - Редкие имена и фамилии (Ковпак, Девятаев) могут быть помечены
  - Топонимы (Сталинград, Рейхстаг) — аналогично
  - Военные термины — могут не распознаваться
  - Это ПОДСКАЗКА, а не приговор — решение за администратором

Если хочешь проверить текст отдельно:
  Открой в браузере: http://127.0.0.1:8080/api/spell-check/?text=твойтекст

  11. ЧАСТЫЕ ОШИБКИ И ИХ РЕШЕНИЯ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ОШИБКА: "python не является командой"
РЕШЕНИЕ:
  Попробуй: py manage.py runserver 8080
  Или укажи полный путь:
    "C:\Users\Artyom\AppData\Local\Programs\Python\Python312\python.exe" manage.py runserver 8080

─────────────────────────────────────────────────────────────────

ОШИБКА: "No module named django" при запуске
ПРИЧИНА: пакеты не установлены
РЕШЕНИЕ: выполни снова:
    python -m pip install -r requirements.txt

─────────────────────────────────────────────────────────────────

ОШИБКА: "That port is already in use" (порт занят)
ПРИЧИНА: сервер уже запущен в другом окне (или был завершён нештатно)
РЕШЕНИЕ:
  Вариант А — использовать другой порт:
    python manage.py runserver 8090
    → открывай http://127.0.0.1:8090/

  Вариант Б — найти и закрыть процесс:
    В новом cmd: netstat -ano | findstr :8080
    Посмотри PID (число в конце строки)
    taskkill /PID [число] /F

─────────────────────────────────────────────────────────────────

ОШИБКА: TemplateDoesNotExist: index.html
ПРИЧИНА: не был запущен setup_template.py
РЕШЕНИЕ:
    python setup_template.py

─────────────────────────────────────────────────────────────────

ОШИБКА: Страница открывается, но добавленные записи не сохраняются
ПРИЧИНА: забыли запустить миграции или сбой базы данных
РЕШЕНИЕ:
    python manage.py migrate

─────────────────────────────────────────────────────────────────

ОШИБКА: Панель /admin/ не открывается (ошибка 403 или пустой экран)
ПРИЧИНА: сервер не запущен или порт другой
РЕШЕНИЕ: убедись что сервер запущен и используй правильный адрес

─────────────────────────────────────────────────────────────────

ОШИБКА: Не помню пароль от admin
РЕШЕНИЕ — сбросить через командную строку:
    python manage.py changepassword admin
  → введи новый пароль дважды

─────────────────────────────────────────────────────────────────

ОШИБКА: "UnicodeDecodeError" при запуске на Windows
РЕШЕНИЕ: запускай команды с префиксом:
    set PYTHONUTF8=1 && python manage.py runserver 8080

─────────────────────────────────────────────────────────────────

ОШИБКА: Сайт открывается но стили/шрифты не работают
ПРИЧИНА: браузер блокирует Google Fonts при отсутствии интернета
РЕШЕНИЕ: убедись что есть подключение к интернету
         (шрифты Playfair Display и PT Serif грузятся с Google)

  12. API-ЭНДПОИНТЫ (СПРАВКА)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Это адреса, по которым сайт обменивается данными с сервером.
Их можно открыть в браузере для проверки:

  ┌─────────────────────────────────┬────────┬──────────────────────┐
  │ Адрес                           │ Метод  │ Действие             │
  ├─────────────────────────────────┼────────┼──────────────────────┤
  │ /api/heroes/                    │ GET    │ Список героев (JSON) │
  │ /api/heroes/                    │ POST   │ Добавить героя       │
  │ /api/heroes/<uuid>/             │ DELETE │ Удалить героя        │
  ├─────────────────────────────────┼────────┼──────────────────────┤
  │ /api/khronika/                  │ GET    │ Список фото хроники  │
  │ /api/khronika/                  │ POST   │ Добавить фото        │
  │ /api/khronika/<uuid>/           │ DELETE │ Удалить фото         │
  ├─────────────────────────────────┼────────┼──────────────────────┤
  │ /api/letters/                   │ GET    │ Список писем         │
  │ /api/letters/                   │ POST   │ Добавить письмо      │
  │ /api/letters/<uuid>/            │ DELETE │ Удалить письмо       │
  ├─────────────────────────────────┼────────┼──────────────────────┤
  │ /api/spell-check/?text=...      │ GET    │ Проверить орфографию │
  └─────────────────────────────────┴────────┴──────────────────────┘

Пример проверки орфографии прямо в браузере:
  http://127.0.0.1:8080/api/spell-check/?text=привет

Пример просмотра всех одобренных героев:
  http://127.0.0.1:8080/api/heroes/

Ответ всегда в формате JSON:
  [] — пустой список (ещё ничего не добавлено или не одобрено)
  [{"id": "uuid...", "name": "...", "approved": false, ...}]

  13. КАК ОСТАНОВИТЬ СЕРВЕР
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

В окне cmd где запущен сервер нажми:
    Ctrl + C

Появится запрос "Terminate batch job? (Y/N)" — нажми Y и Enter.

Сервер остановлен. Сайт больше не открывается до следующего запуска.
Данные в db.sqlite3 сохраняются — ничего не теряется.

  14. РЕЗЕРВНОЕ КОПИРОВАНИЕ ДАННЫХ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Все данные (пользовательские записи, одобренные материалы)
хранятся в одном файле:

    wwii_backend\db.sqlite3

Чтобы сделать резервную копию:
  - Останови сервер (Ctrl+C)
  - Скопируй файл db.sqlite3 в другое место
  - Например: db.sqlite3.backup-2026-05-03

Чтобы восстановить из копии:
  - Останови сервер
  - Замени db.sqlite3 файлом из резервной копии
  - Запусти сервер заново

Экспорт всех данных в текстовый файл (JSON):
    python manage.py dumpdata content > backup_content.json

Импорт из JSON-файла:
    python manage.py loaddata backup_content.json
